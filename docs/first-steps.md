# Первый практический шаг

Цель первого занятия — получить рабочую цепочку «исходники → сборка → прошивка → UART-лог».
Анализатор и его периферия подключаются после этого результата.

## 1. Подтвердить железо

Записать точную маркировку платы и модуля, например `ESP32-DevKitC` и
`ESP32-WROOM-32E`. Название «ESP32» само по себе не определяет распиновку платы.
Уточнить наличие SSD1306 128×64 с I²C, двух кнопок, макетной платы и проводов.

Для первого запуска достаточно самой ESP32 и USB-кабеля с передачей данных.
Перед первой прошивкой определить последовательный порт именно этой платы.

## 2. Выбрать правильное окружение ESP-IDF

В проекте выбрана версия **v5.5.6**, цель **esp32**. Установить её по
[официальному руководству ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.5.6/esp32/get-started/index.html)
или через Espressif Installation Manager, выбрав именно эту версию.
Окружение другой версии можно сохранить рядом; удалять его не требуется.

Пути к SDK и к собираемому приложению должны быть без пробелов. Каталог этого
репозитория с именем `ESP32 WIFI SCOPE` не подходит для прямой сборки; первый пример
ниже специально размещается отдельно, в `esp-experiments/scope-hello-world`.

В терминале с активированным окружением выполнить:

```sh
idf.py --version
```

Ожидается `ESP-IDF v5.5.6`. Если показана другая версия, переключить окружение
до сборки. Не смешивать Python/toolchain одной установки с SDK другой.

## 3. Собрать официальный пример отдельно от проекта

Эти команды выполняются в активированном окружении v5.5.6.
Каталог назначения должен быть новым: если он уже есть, использовать другое имя.

```sh
mkdir -p "$HOME/esp-experiments"
cp -R "$IDF_PATH/examples/get-started/hello_world" "$HOME/esp-experiments/scope-hello-world"
cd "$HOME/esp-experiments/scope-hello-world"
idf.py set-target esp32
idf.py build
```

Пример берётся из закреплённой установки SDK, а не из `master` в интернете.
В этом репозитории пока нет `app_main` и CMake-проекта: команда `idf.py build`
в его корне ещё не должна работать.

## 4. Найти порт и выполнить первый запуск

На macOS список последовательных портов можно посмотреть до и после подключения:

```sh
ls /dev/cu.*
```

Определить порт именно своей платы. В командах ниже заменить `<PORT>` его
реальным именем; угловые скобки являются обозначением, не частью команды.

```sh
idf.py -p <PORT> -b 115200 flash monitor
```

В логе должны появиться `Hello world!` и информация о ESP32. Официальный пример
может затем выполнить плановый перезапуск — это не сбой анализатора.
Из IDF Monitor выходят сочетанием `Ctrl+]`.

Сохранить версию SDK, модель платы и результат запуска. На этом первое занятие
закончено: дальше создаётся собственное минимальное приложение проекта.

## 5. Подготовить подключение периферии

Предварительный профиль для обычной ESP32-WROOM DevKit:

| Устройство | Сигнал | ESP32 |
| --- | --- | --- |
| SSD1306 I²C | SDA | GPIO21 |
| SSD1306 I²C | SCL | GPIO22 |
| SSD1306, модуль с поддержкой питания 3,3 В | VCC / GND | 3V3 / GND |
| Кнопка «Далее» | Контакт / второй контакт | GPIO25 / GND |
| Кнопка «Выбор» | Контакт / второй контакт | GPIO26 / GND |

GPIO кнопок будут настроены со внутренней подтяжкой вверх; нажатие даёт логический
ноль. Для I²C проверить наличие подтяжек на модуле и их подключение к 3,3 В.
Окончательную схему сверить с маркировкой конкретной платы и дисплея до сборки.
Сейчас таблица — выбранный профиль, а не проверенная на твоём железе схема.

Справочные материалы: [ESP32-DevKitC](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html),
[SSD1306 / esp_lcd](https://docs.espressif.com/projects/esp-idf/en/v5.5.6/esp32/api-reference/peripherals/lcd/index.html).
