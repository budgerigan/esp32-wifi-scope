# Первый запуск платы — 2026-11-06

## Идентификация

Плата подключена через USB-UART. Надпись `CH340C`, указанная владельцем,
обозначает USB-UART мост, а не модель микроконтроллера.

| Параметр | Наблюдение |
| --- | --- |
| Микроконтроллер | ESP32-D0WD-V3, silicon revision 3.1 |
| Возможности чипа | Два CPU-ядра, до 240 МГц, Wi-Fi и Bluetooth |
| Кварц | 40 МГц |
| Внешняя flash | 4 МБ, определено через `esptool flash-id` |
| USB-UART | CH340C по маркировке; порт определяется macOS |
| Цель сборки | `esp32` |
| Выбранный SDK | ESP-IDF v5.5.6 |
| OLED и кнопки | Есть у владельца; электрическое подключение и работа ещё не проверены |

Модель кристалла не устанавливает точную модель DevKit или распиновку её разъёмов.
Выбранные GPIO остаются предварительными до сверки конкретной платы.

## Связь и сохранение текущей flash

Чтение резервной копии на 460800 бод завершилось ошибкой повреждения данных.
Для следующих операций выбрана скорость 115200 бод. Причина ошибки на повышенной
скорости не установлена: её нельзя без отдельной проверки приписывать самому CH340C.

Полная резервная копия прочитана на 115200 бод: **4 194 304 байта**.
Она находится локально в игнорируемом каталоге `captures/` и не публикуется в GitHub.
Неудачная попытка чтения на повышенной скорости не считается резервной копией.

## Окружение

SDK соответствует tag **v5.5.6**, commit
`880a203ae603d08a94d06aa01e0d6761958e5e9e`. Для него установлены обязательные
инструменты через штатный `idf_tools.py` и отдельный Python venv.
Существующая установка v6.1 сохранена.

| Компонент | Использованная версия |
| --- | --- |
| ESP-IDF | v5.5.6 |
| Xtensa GCC | esp-14.2.0_20260121 |
| Python | 3.14.8, отдельный `idf5.5_py3.14_env` |
| CMake | 3.30.2 |
| Ninja | 1.12.1 |
| esptool при прошивке | 4.13.0 |

Первоначальная попытка установки через EIM была остановлена; этот SDK активируется
через его `export.sh`, как показано ниже, а не через незавершённую запись EIM.

## Первый пример

Для проверки цепочки сборки используется неизменённый исходник официального
`examples/get-started/hello_world` из ESP-IDF v5.5.6.
В локальной копии добавлены только настройки платы:

```text
CONFIG_ESPTOOLPY_FLASHSIZE_4MB=y
CONFIG_ESPTOOLPY_FLASHMODE_DIO=y
```

Источник примера и SDK размещаются в каталогах без пробелов. Рабочая папка этого
репозитория может хранить документацию, но её текущее имя с пробелами не подходит
для прямой сборки ESP-IDF. Сборка собственного приложения будет выполняться из
отдельного рабочего каталога без пробелов.

**Результат: сборка, прошивка и UART-проверка прошли успешно.**

- Размер `hello_world.bin`: **136 992 байта**; SHA-256:
  `0be0ce8e5d076edde8829781eaf4d17b38f86f5c16bae76316dd74470cf1d391`.
- Режим flash: DIO, 40 МГц, 4 МБ; запись выполнена на 115200 бод.
- esptool подтвердил хеши записанных bootloader, приложения и таблицы разделов.
- За 25 секунд UART-наблюдения получено **три** сообщения `Hello world!`.
- Лог подтвердил v5.5.6, silicon revision 3.1, два ядра и 4 МБ внешней flash.
- Частота CPU в этом примере — **160 МГц**; 240 МГц в таблице выше — возможность чипа.
- `Minimum free heap size`: **304 988 байт** для этого примера; это не бюджет будущего анализатора.
- Наблюдались штатные программные перезапуски примера; сообщений panic/abort в захваченном логе нет.

Фрагмент UART:

```text
ESP-IDF:          v5.5.6
Hello world!
This is esp32 chip with 2 CPU core(s), WiFi/BTBLE, silicon revision v3.1, 4MB external flash
Minimum free heap size: 304988 bytes
Restarting in 10 seconds...
```

В загрузочном логе есть предупреждение о Boya flash с generic-драйвером.
Оно не помешало записи и запуску; при подготовке собственной конфигурации платы
нужно рассмотреть `CONFIG_SPI_FLASH_SUPPORT_BOYA_CHIP`.

Этот пример не реализует функции Wi-Fi Analyzer и не подтверждает работу OLED,
радиозахвата, очередей или восьмичасовую устойчивость.

## Повторить на текущем macOS-стенде

Открыть новый терминал и активировать именно это окружение:

```sh
export PATH="$HOME/.espressif/tools/cmake/3.30.2/CMake.app/Contents/bin:$HOME/.espressif/tools/ninja/1.12.1:/opt/homebrew/bin:$PATH"
export IDF_TOOLS_PATH="$HOME/.espressif"
. "$HOME/.espressif/esp32-wifi-scope/v5.5.6/esp-idf/export.sh"
cd "$HOME/esp-experiments/scope-hello-world"
idf.py --version
idf.py -p /dev/cu.usbserial-10 monitor
```

Ожидаемая версия — `ESP-IDF v5.5.6`. Выход из монитора — `Ctrl+]`.
Имя порта может измениться при переподключении; актуальный список: `ls /dev/cu.*`.
Для повторной сборки и записи после изменения примера:

```sh
idf.py build
idf.py -p /dev/cu.usbserial-10 -b 115200 flash monitor
```

Исходник для первого самостоятельного эксперимента:
`$HOME/esp-experiments/scope-hello-world/main/hello_world_main.c`.
Можно изменить строку приветствия, повторить сборку/запись и увидеть свой текст.
